# Taxi Chat Dashboard

MVP-дашборд для анализа Telegram-чатов такси: сообщения → обсуждения → инфоповоды.

## Что делает проект

1. Загружает исходный CSV с разделителем `;` и кодировкой UTF-8 BOM.
2. Нормализует поля: дата, чат, автор, текст, ссылки, тональность, токсичность.
3. Превращает бинарные колонки тегов в нормальный список тегов.
4. Собирает первичные обсуждения:
   - комментарии группируются по `Ссылка на родительский пост`;
   - остальные сообщения группируются внутри чата по временному окну и пересечению тегов.
5. Кластеризует обсуждения в инфоповоды.
6. Создает таблицы:
   - `messages`
   - `message_tags`
   - `discussions`
   - `discussion_messages`
   - `events`
   - `event_discussions`
7. Запускает Streamlit-дашборд.
8. Хранит ручные правки, скрытия, статусы, объединения и перенос сообщений в SQLite.

## Быстрый старт

```bash
cd taxi_chat_dashboard
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements-preprocess.txt
```

Положите исходный CSV в папку `data/`, например:

```text
data/chats.csv
```

Предобработка:

```bash
python src/preprocess.py --input data/chats.csv --output data/processed --window-minutes 60 --cluster-method tfidf --event-gap-hours 1
```

Запуск дашборда:

```bash
streamlit run src/app.py -- --data-dir data/processed --db-path data/manual_actions.sqlite
```

## Рекомендуемый первый режим

Для старта используйте:

```bash
python src/preprocess.py --input data/chats.csv --output data/processed --window-minutes 60 --cluster-method tfidf --similarity-threshold 0.25 --event-gap-hours 1
```

Если инфоповоды получаются слишком крупными — увеличьте `--similarity-threshold`, например до `0.35`.
Если слишком дробными — уменьшите до `0.20` или увеличьте `--event-gap-hours`, например до `6` или `12`.

## Ручные действия в дашборде

В интерфейсе можно:

- переименовать инфоповод;
- изменить краткое описание;
- поставить статус;
- скрыть инфоповод;
- объединить один инфоповод с другим;
- перенести выбранное сообщение в другой инфоповод;
- скрыть отдельное сообщение.

Все правки пишутся в `manual_actions.sqlite`, исходный CSV не меняется.

## Важное замечание

Кластеризация в MVP намеренно сделана безопасной и объяснимой. Она группирует не отдельные сообщения, а уже собранные обсуждения. Это снижает шум от коротких реплик, OCR и расшифровок.

## Версия 0.2 — упрощенный дашборд и улучшенная кластеризация

Что изменено:

- главный экран теперь сфокусирован на инфоповодах, а не на техническом обзоре;
- скрыты технические ID и лишние колонки;
- сообщения вынесены внутрь карточки выбранного инфоповода;
- добавлен компактный режим просмотра ключевых сообщений;
- мат, служебные и слишком общие слова больше не попадают в названия инфоповодов;
- широкие темы дополнительно дробятся на временные волны через `--event-window-hours`;
- добавлены более понятные шаблоны названий: WB Такси, забастовка, налоги, коэффициенты, Яндекс Про;
- ручная правка, объединение инфоповодов, перенос и скрытие сообщений сохранены.

Рекомендуемая команда пересборки данных:

```bash
python src/preprocess.py --input data/chats.csv --output data/processed --window-minutes 60 --cluster-method tfidf --similarity-threshold 0.32 --event-gap-hours 1 --event-window-hours 12
```

Как калибровать алгоритм:

- `--similarity-threshold` выше — темы дробнее;
- `--similarity-threshold` ниже — темы шире;
- `--event-window-hours 12` — инфоповоды делятся на полусуточные волны;
- `--event-window-hours 24` — меньше инфоповодов, темы крупнее;
- `--event-window-hours 0` — отключить дробление по фиксированным временным окнам.

Для публикации изменений в Streamlit Cloud: внесите правки локально, сделайте commit и push в GitHub. Streamlit Cloud подтянет изменения из репозитория.


## Версия 0.4 — нерелевантные сообщения

В карточке инфоповода во вкладке **Вся лента** можно выбрать сообщение и нажать **Нерелевант**.  
Это действие не удаляет сообщение и не скрывает его глобально: оно исключает сообщение только из текущего инфоповода.

Во вкладке **Правки** появился блок **Нерелевантные сообщения**. Там можно посмотреть исключенные сообщения и вернуть их обратно в инфоповод.

Ручные исключения хранятся в SQLite-таблице `event_message_exclusions`.
