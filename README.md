# Taxi Chat Dashboard

MVP-дашборд для анализа Telegram-чатов такси: сообщения → обсуждения → инфоповоды.

## Что делает проект

1. Загружает исходный CSV с разделителем `;` и кодировкой UTF-8 BOM.
2. Нормализует поля: дата, чат, автор, текст, ссылки, тональность, токсичность.
3. Превращает бинарные колонки тегов в нормальный список тегов.
4. Собирает первичные обсуждения:
   - комментарии группируются по `Ссылка на родительский пост`;
   - остальные сообщения группируются внутри чата по временному окну и пересечению тегов.
5. Кластеризует обсуждения в инфоповоды.
6. Создает таблицы:
   - `messages`
   - `message_tags`
   - `discussions`
   - `discussion_messages`
   - `events`
   - `event_discussions`
7. Запускает Streamlit-дашборд.
8. Хранит ручные правки, скрытия, статусы, объединения и перенос сообщений в SQLite.

## Быстрый старт

```bash
cd taxi_chat_dashboard
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements-preprocess.txt
```

Положите исходный CSV в папку `data/`, например:

```text
data/chats.csv
```

Предобработка:

```bash
python src/preprocess.py --input data/chats.csv --output data/processed --window-minutes 60 --cluster-method tfidf --event-gap-hours 1
```

Запуск дашборда:

```bash
streamlit run src/app.py -- --data-dir data/processed --db-path data/manual_actions.sqlite
```

## Рекомендуемый первый режим

Для старта используйте:

```bash
python src/preprocess.py --input data/chats.csv --output data/processed --window-minutes 60 --cluster-method tfidf --similarity-threshold 0.25 --event-gap-hours 1
```

Если инфоповоды получаются слишком крупными — увеличьте `--similarity-threshold`, например до `0.35`.
Если слишком дробными — уменьшите до `0.20` или увеличьте `--event-gap-hours`, например до `6` или `12`.

## Ручные действия в дашборде

В интерфейсе можно:

- переименовать инфоповод;
- изменить краткое описание;
- поставить статус;
- скрыть инфоповод;
- объединить один инфоповод с другим;
- перенести выбранное сообщение в другой инфоповод;
- создать новый инфоповод вручную, если нужной темы нет в списке;
- создать новый инфоповод прямо из выбранного сообщения и сразу перенести его туда;
- скрыть отдельное сообщение.

Все правки пишутся в `manual_actions.sqlite`, исходный CSV не меняется.

## Важное замечание

Кластеризация в MVP намеренно сделана безопасной и объяснимой. Она группирует не отдельные сообщения, а уже собранные обсуждения. Это снижает шум от коротких реплик, OCR и расшифровок.

## Версия 0.2 — упрощенный дашборд и улучшенная кластеризация

Что изменено:

- главный экран теперь сфокусирован на инфоповодах, а не на техническом обзоре;
- скрыты технические ID и лишние колонки;
- сообщения вынесены внутрь карточки выбранного инфоповода;
- добавлен компактный режим просмотра ключевых сообщений;
- мат, служебные и слишком общие слова больше не попадают в названия инфоповодов;
- широкие темы дополнительно дробятся на временные волны через `--event-window-hours`;
- добавлены более понятные шаблоны названий: WB Такси, забастовка, налоги, коэффициенты, Яндекс Про;
- ручная правка, объединение инфоповодов, перенос и скрытие сообщений сохранены.

Рекомендуемая команда пересборки данных:

```bash
python src/preprocess.py --input data/chats.csv --output data/processed --window-minutes 60 --cluster-method tfidf --similarity-threshold 0.32 --event-gap-hours 1 --event-window-hours 12
```

Как калибровать алгоритм:

- `--similarity-threshold` выше — темы дробнее;
- `--similarity-threshold` ниже — темы шире;
- `--event-window-hours 12` — инфоповоды делятся на полусуточные волны;
- `--event-window-hours 24` — меньше инфоповодов, темы крупнее;
- `--event-window-hours 0` — отключить дробление по фиксированным временным окнам.

Для публикации изменений в Streamlit Cloud: внесите правки локально, сделайте commit и push в GitHub. Streamlit Cloud подтянет изменения из репозитория.


## Версия 0.4 — нерелевантные сообщения

В карточке инфоповода во вкладке **Вся лента** можно выбрать сообщение и нажать **Нерелевант**.  
Это действие не удаляет сообщение и не скрывает его глобально: оно исключает сообщение только из текущего инфоповода.

Во вкладке **Правки** появился блок **Нерелевантные сообщения**. Там можно посмотреть исключенные сообщения и вернуть их обратно в инфоповод.

Ручные исключения хранятся в SQLite-таблице `event_message_exclusions`.


## Версия 0.5 — более точное определение инфоповодов

В этой версии изменен алгоритм группировки:

- комментарии под одним родительским постом больше не склеиваются автоматически в одно обсуждение; крупные ветки дополнительно режутся по времени, тегам и микротеме;
- перед кластеризацией каждому сообщению и обсуждению назначается `microtopic`: `coeff_priority`, `app_bug`, `tax_law`, `wb_launch`, `fasten_service`, `payments`, `account_block`, `gps_map` и т.д.;
- кластеризация идет не по всем сообщениям сразу, а внутри узких корзин: основной тег + микротема + временное окно;
- широкие темы вроде «яндекс» и «Коэффициент» используют более строгий порог похожести;
- родительский пост добавляется в текст обсуждения только как короткий контекст, чтобы он не склеивал разные комментарии в один инфоповод.

Рекомендуемая команда пересборки данных:

```bash
python src/preprocess.py --input data/chats.csv --output data/processed --window-minutes 60 --cluster-method tfidf --similarity-threshold 0.28 --event-gap-hours 3 --event-window-hours 16
```

Если инфоповодов слишком много, уменьши точность и сделай темы крупнее:

```bash
python src/preprocess.py --input data/chats.csv --output data/processed --similarity-threshold 0.25 --event-gap-hours 4 --event-window-hours 24
```

Если в одном инфоповоде снова появляются лишние сообщения, сделай темы строже:

```bash
python src/preprocess.py --input data/chats.csv --output data/processed --similarity-threshold 0.34 --event-gap-hours 2 --event-window-hours 12
```


## Версия 0.6 — формат даты в интерфейсе

В пользовательских таблицах дата отображается без времени в формате `ДД.ММ.ГГГГ`.

Внутри данных поля `datetime`, `start_date` и `end_date` остаются полноценными датами со временем, чтобы не ломать сортировку, группировку и алгоритмы инфоповодов.


## Версия 0.7 — объединение одинаковых тем

Что изменено:

- из боковой панели убран слайдер `Минимум сообщений`;
- одинаковые названия инфоповодов автоматически объединяются в одну строку дашборда;
- исходные детальные события не удаляются: объединение выполняется на уровне отображения и связей сообщений;
- сообщения из одинаковых тем суммируются в общей карточке темы;
- ручное объединение, перенос, скрытие и отметка `Нерелевант` продолжают работать поверх автоматического объединения.

## Версия 0.8 — упрощение карточки инфоповода

Из карточки инфоповода убран визуальный блок с ключевыми фразами. Ключевые слова и фразы остаются в данных и могут использоваться алгоритмами, но больше не отображаются пользователю в интерфейсе.

## Версия 0.9 — тезисные описания инфоповодов

Колонка **Описание** теперь формируется не как техническое резюме с датами и ключевыми словами, а как пользовательский тезис:

```text
В теме обсуждались: законопроект и новые требования к работе такси; повышение или снижение коэффициентов; невозможность загрузить или установить обновление.
```

Описание строится по сообщениям внутри уже объединенной темы. Алгоритм учитывает частые смысловые сигналы: законы и налоги, коэффициенты, тарифы, сбои приложения, обновления, блокировки, выплаты, забастовки, WB Такси, Фастен, навигацию, аэропорты и другие повторяющиеся сюжеты.

Во вкладке **Правки** можно вручную скорректировать описание. После сохранения ручной текст будет показываться в таблице инфоповодов и в карточке вместо автоматического описания.

## Версия 1.0 — загрузка CSV из дашборда

В интерфейс добавлен раздел **«Загрузка CSV»**. Он позволяет загрузить новый CSV-файл периода и пересобрать таблицы `messages`, `discussions`, `events` и связи между ними без ручного запуска `preprocess.py`.

### Как использовать

1. Откройте дашборд.
2. В левом меню выберите **«Загрузка CSV»**.
3. Загрузите новый CSV-файл.
4. Выберите режим:
   - **Заменить текущую выборку новым CSV** — дашборд будет построен только по новому файлу.
   - **Добавить CSV в историю загрузок и пересобрать все загруженные периоды** — новый файл добавится в `data/uploads`, после чего дашборд пересоберет темы по всем CSV из этой папки.
5. При необходимости измените параметры алгоритма.
6. Нажмите **«Загрузить и пересобрать»**.

### Важно про Streamlit Cloud

На Streamlit Cloud файлы, загруженные через интерфейс, сохраняются только в текущем runtime. После redeploy, перезапуска окружения или сброса приложения данные могут вернуться к состоянию из GitHub. Для постоянного обновления нужно:

- либо после проверки скачать/перенести обновленные файлы из `data/processed` и отправить их в GitHub;
- либо подключить внешнее хранилище/БД для исходных CSV и ручных правок.

Для локальной работы загрузка сохраняет файлы в папку `data/uploads`, а обработанные таблицы — в `data/processed`.


## Версия 1.1 — корректное объединение тем

Исправлено ручное объединение инфоповодов. Раньше кнопка «Объединить» переносила только один внутренний `event_id`, поэтому у крупных автоматически объединенных тем могла переноситься лишь небольшая часть сообщений. Теперь при объединении переносится вся видимая тема целиком: все исходные события/волны обсуждения, которые скрыты под выбранной строкой в дашборде.


## Версия 1.2 — ручное создание инфоповодов

Добавлена возможность самостоятельно заводить инфоповод, если нужной темы нет в списке.

Где доступно:

- в боковой панели раздела «Инфоповоды» — блок «Создать инфоповод»;
- в карточке инфоповода: «Вся лента» → выбрать сообщение → «Создать новый инфоповод для этого сообщения».

Новый инфоповод сохраняется в SQLite (`manual_actions.sqlite`), появляется в общей таблице тем и становится доступен в списке для переноса сообщений. Если инфоповод создан из сообщения, выбранное сообщение сразу переносится в новую тему.



## Версия 1.3 — фильтр по слову в сообщениях

Изменения:

- фильтр «Поиск по теме» заменен на фильтр **«Слово в тексте сообщений»**;
- поиск идет именно по тексту сообщений, а не по названию или описанию инфоповода;
- при вводе слова дашборд выводит отдельную таблицу **«Сообщения со словом...»**;
- в таблицу попадают все найденные сообщения с датой, чатом, автором, инфоповодом, текстом и ссылкой;
- список инфоповодов ниже автоматически ограничивается темами, в которых есть найденные сообщения.

Пример: если ввести `коэффициент`, дашборд покажет все сообщения, где это слово встречается в тексте, и только связанные с ними инфоповоды.
